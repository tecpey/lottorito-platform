# وضعیت واقعی پروژه و نقطه ادامه کار

**شناسه:** LOT-OPS-001 | **نسخه:** 0.2.0 | **بازبینی:** ۲۰۲۶-۱۱-۲۴

## وضعیت تأییدشده
- مخزن tecpey/lottorito-platform وجود دارد؛ شاخه پیش‌فرض main و سطح دسترسی Public است و طبق تصمیم فعلی مالک پابلیک می‌ماند.
- اتصال GitHub مجوزهای admin، maintain، push، pull و triage را گزارش کرده است.
- فایل‌های docs/fa/README.md و docs/en/README.md ساخته شده و محتوایشان مجدداً از GitHub خوانده شده است.
- اسناد پایه محصول، راهنمای ایجنت و نقطه ادامه کار در حال ثبت هستند.

## به‌روزرسانی خط مبنای مستندات در ۲۰۲۶-۱۱-۲۴
- LOT-AGENT-001: راهنمای دوزبانه و کم‌Context برای ایجنت‌ها و مشارکت‌کنندگان.
- LOT-ADR-REG-001: دفتر دوزبانه تفکیک دستور مالک، پیشنهاد و تصمیم باز.
- LOT-LOTTERY-001: PRD پیشنهادی کشف Lottery؛ بدون مجوز پیاده‌سازی یا راه‌اندازی.
- LOT-LOTINT-001: قرارداد پیشنهادی چرخه عمر مستقل از Provider؛ بدون API یا Sandbox تأییدشده.
- LOT-DOM-001: مدل Bounded Context و ERD منطقی بین‌محصولی پیشنهادی؛ هیچ Schema فیزیکی تصویب نشده است.
- LOT-TEN-001: مدل پیشنهادی جداسازی Tenant و انتشار Context؛ پیاده‌سازی یا شواهد تست منفی وجود ندارد.
- LOT-EVENT-001: پاکت canonical و قرارداد تحویل رویداد پیشنهادی؛ API یا Schema Registry پیاده‌سازی نشده است.
- هر دو فهرست مستندات برای مسیریابی به این مراجع به‌روزرسانی شده‌اند.
- این تغییرات روی شاخه docs/agent-ready-foundation-v1 هستند و به main ادغام نشده‌اند.

## هنوز تأیید نشده
هیچ کد اجرایی، schema دیتابیس، CI workflow، کنترل خودکار همگامی زبان‌ها، اتصال API شریک، Sandbox، محاسبه مالی، پرداخت یا Deploy عملیاتی تأیید نشده است. ادعای موفقیت تست یا Deploy بدون شواهد ممنوع است.

## دستور ادامه برای هر ایجنت
1. این سند و AGENTS.md را بخوان.
2. اسناد مرتبط را در هر دو زبان بخوان.
3. وضعیت واقعی شاخه‌ها، فایل‌ها، Issueها و PRها را بررسی کن.
4. پیش از ایجاد هر چیز، وجود کار مشابه را جست‌وجو کن.
5. ابهام‌ها را به پرسش یا Issue تبدیل کن؛ فرض را قانون نکن.
6. تغییرات را دوزبانه، تست‌شده و همراه شواهد تحویل بده.

## ترتیب بعدی
۱. تکمیل مدل دامنه بین‌محصولی، Bounded Contextها، نقشه مالکیت و ERD.
۲. تعریف مدل صریح Tenant/Identity و Threat Model.
۳. تعریف استانداردهای canonical API و پاکت رویداد مشترک، شامل شناسه رویداد منبع، اثر اقتصادی و سند دفترکل.
۴. تکمیل ثبت مالی، تطبیق، کنترل پرداخت و نگاشت حساب‌های محصول/Tenant.
۵. تدوین ADR فناوری، استقرار، قابلیت اطمینان و محل نگهداری داده با معیارهای تصمیم.
۶. افزودن کنترل خودکار هم‌ارزی زبان‌ها، لینک‌ها و Metadata مستندات.
۷. فقط پس از تصمیم مالک و شواهد لازم، ایجاد اسکلت پلتفرم و پیاده‌سازی عمودی مستقل.

## تصمیم‌های موردنیاز مالک
ماهیت اعتبار تبلیغاتی ۱۰۰ دلاری، تعریف NGR، درصد و توزیع کمیسیون، قواعد ارتقا، سیاست برداشت، حوزه‌های قضایی و جزئیات API شریک.
