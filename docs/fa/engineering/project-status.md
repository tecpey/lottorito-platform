## نتیجه ممیزی اولیه
پایه مستنداتی برای طراحی تفصیلی مناسب است، اما قرارداد واقعی شریک و Sandbox، OpenAPI/Event Contract کامل، تعریف‌های مالی، Attribution، QA Strategy، Threat Model/Data Governance، UX و SRE/Operations نیازمند تکمیل‌اند. جزئیات در `LOT-AUDIT-DOC-001` ثبت شده‌اند.

## هنوز تأیید نشده
هیچ کد اجرایی برنامه، schema/migration اجرایی، test suite، GitHub Actions workflow، کنترل خودکار parity، اتصال API شریک، Sandbox، محاسبه مالی، پرداخت یا Deploy عملیاتی تأیید نشده است. برای head فعلی PR شماره ۷، status check ثبت‌شده‌ای گزارش نشده است. نبود status check به معنی موفقیت تست نیست.

## دستور ادامه برای هر ایجنت
1. این سند و `AGENTS.md` را بخوان.
2. اسناد مرتبط را در هر دو زبان بخوان؛ مخصوصاً `LOT-DATA-001` و `LOT-AUDIT-DOC-001`.
3. وضعیت واقعی شاخه‌ها، فایل‌ها، Issueها و PRها را مجدداً از GitHub بررسی کن؛ SHA این سند فقط snapshot زمان بازبینی است.
4. پیش از ایجاد هر چیز، Issueها و PRهای موجود را جست‌وجو کن؛ LOT-001 تا LOT-006 را تکرار نکن.
5. ابهام‌ها را به پرسش یا Issue تبدیل کن؛ فرض را قانون نکن.
6. تغییرات مستندات را در هر دو زبان، در یک PR و همراه شواهد تحویل بده.
7. سند مفهومی را با migration یا schema اجرایی اشتباه نگیر؛ ابتدا تصمیمات باز و ADRها را حل کن.
8. هیچ Merge، Deploy یا عملیات مالی/تولیدی بدون مجوز لازم انجام نده.

## ترتیب بعدی
1. بازبینی تخصصی PR شماره ۷ و بررسی parity فارسی/انگلیسی.
2. تکمیل LOT-001 تا LOT-006 و پاسخ مستند به DATA-Q01 تا DATA-Q12.
3. تکمیل اسناد جدید Issueهای ۱۰ تا ۱۴.
4. دریافت قرارداد واقعی و Sandbox شریک.
5. ADRهای فناوری و دیتابیس، سپس logical schema و migration.
6. پیاده‌سازی parity CI، تست‌ها و اسکلت برنامه.
7. اجرای میزگرد نهایی پس از تکمیل MVP و پیش از تأیید آمادگی انتشار.
