# قرارداد اتصال شرکای تجاری

**شناسه:** LOT-INT-001 | **نسخه:** 0.2.0 | **وضعیت:** پیش‌نویس؛ قرارداد واقعی RaidenBet دریافت/تأیید نشده

## اصل اتصال
هسته فقط با مدل canonical داخلی کار می‌کند. هر شریک Adapter اختصاصی دارد؛ منطق خاص شریک نباید وارد Commission Core یا Ledger شود.

## مسئولیت Adapter
اعتبارسنجی اصالت و امضا؛ دریافت رویداد و reconciliation؛ نگاشت شناسه خارجی؛ نرمال‌سازی ارز/زمان/وضعیت؛ deduplication و idempotency؛ مدیریت نسخه API؛ retry، dead-letter و replay کنترل‌شده؛ ثبت provenance و trace ID.

## رویدادهای احتمالی
ثبت‌نام، واریز، برداشت، فعالیت واجد شرایط، اصلاح NGR، برگشت و مسدودسازی. وجود و معنای هر رویداد باید از سند واقعی شریک تأیید شود.

## امنیت
TLS؛ امضای webhook یا احراز هویت توافق‌شده؛ نگهداری و چرخش امن secret خارج از Git؛ timestamp و replay protection؛ محدودیت نرخ و اندازه payload؛ عدم ثبت token یا داده حساس در log.

## وضعیت پایلوت
### قرارداد پیشنهادی دریافت رویداد و معیارهای پذیرش (LOT-004)

| حالت | نتیجه لازم |
|---|---|
| ارسال مجدد هم‌زمان؛ توقف پردازشگر پس از ثبت مالی و پیش از تأیید | دریافت احرازشده پیش از تأیید وصول به‌طور پایدار ذخیره شود. هر اثر مالی و کلید یکتای پردازش آن در یک تراکنش ثبت شوند. در تلاش مجدد، نتیجه ثبت‌شده بازگردد؛ دقیقاً یک ثبت مالی باقی بماند. |
| کلید یکسان، محتوای مالی متفاوت | فیلدهای تجاری نرمال‌شده بدون فراداده انتقال مقایسه شوند. تعارض قرنطینه شود و ارجاع هر دو دریافت برای تطبیق حفظ شود. ثبت اولیه بازنویسی نشود. |
| شناسه خارجی یکسان روی دو اتصال | Tenant و اتصال از اعتبارنامه احرازشده تعیین شوند. هر اتصال دامنه هویت قراردادی خود را دارد؛ تعارض Tenant در پیام پیش از اعمال اثر رد شود. |
| دریافت برگشت پیش از رویداد اصلی | ارجاع حل‌نشده معلق بماند؛ رویداد اصلی در همان اتصال تطبیق داده شود. پس از تطبیق، سیاست مصوب برگشت یک‌بار اعمال شود؛ ترتیب دریافت مبنای ترتیب وقوع نیست. |
| دامنه یکتایی تضمین نشده یا نسخه schema ناشناخته | همراه دلیل قرنطینه شود. تا تأیید نگاشت و قواعد هویت، اثر مالی اعمال نشود. بازپخش مجاز از شناسه اثر اولیه استفاده کند، نه کلید جدید. |

مبنای طراحی: [مستند دریافت رویداد Stripe](https://docs.stripe.com/webhooks) ارسال تکراری و دریافت خارج از ترتیب را توضیح می‌دهد؛ [راهنمای AWS درباره APIهای تکرارپذیر](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) تلاش مجدد را از تغییر مقصود درخواست تفکیک می‌کند. این منابع مبنای انتخاب سناریوها هستند، نه مدرک رفتار RaidenBet. پیش از تصویب Adapter شریک، نمونه پیام‌های امضاشده، دامنه یکتایی شناسه، بازه تلاش مجدد، منبع داده تطبیق و قواعد اصلاح رویداد دریافت شوند.

### شواهد موجود
RaidenBet شریک پایلوت پیشنهادی است. هنوز endpoint، credential، sandbox، schema وب‌هوک یا رفتار واقعی API در مخزن تأیید نشده؛ پس اتصال عملیاتی انجام‌شده تلقی نمی‌شود.
