## ۱. هدف و مرز

RDM-004 برای تمام ۳۶ ردیف پنج جدول تصمیم DT-01 تا DT-05، راستی‌آزمایی اجرایی ردیف‌محور اضافه می‌کند. هدف، بستن فاصله میان داشتن جدول‌های تصمیم قابل‌خواندن برای انسان و وجود آزمون اجرایی صریح برای هر ردیف اعلام‌شده است.

Runner در فایل `tools/lot_eval_rdm004.py` قرار دارد. این ابزار فقط از کتابخانه استاندارد Python و Fixtureهای ساختگی قطعی استفاده می‌کند. هیچ وابستگی به شبکه، دیتابیس، Provider، Credential، Runtime محصول یا داده Production ندارد و توسط کد محصول Import نمی‌شود.

این فعالیت، ساخت مدل مرجع و Oracle آزمون به‌دست نویسنده است؛ بازبینی کور، بازبینی نفر دوم، تضمین مستقل، IV&V رسمی، مشاوره حقوقی، گواهی، پذیرش مالک یا تصویب LOT-EVAL-001 محسوب نمی‌شود.

## ۲. منابع تثبیت‌شده و دامنه

کاتالوگ تصمیم با مقررات مرتبط سند مادر تطبیق داده می‌شود:
- §4 — سطح‌بندی واحد تصمیم دقیق و قاعده بالاترین محرک؛
- §7 — Gateهای اجباری غیرقابل‌جبران و آزمایش محدود مشروط؛
- §8.3 و §17.10.1 — وضعیت شواهد، لنگرهای قابلیت ۰ تا ۵، معنای N/A و NS؛
- §17.10.2 — تفکیک اختیار منبع، استقلال و اطمینان؛
- §17.10.3 — واحد تصمیم دقیق و مرز آزمایش مصنوعی؛
- §17.10.4 — فیلدهای کامل رکورد ریسک، افق و زوج خام احتمال/اثر.

۳۶ ردیف جدول، تعهدات راستی‌آزمایی هستند؛ نه ۳۶ آزمون مستقل End-to-End. RDM-004 ادعای راستی‌آزمایی کامل ۱۸ قاعده اتمی، تمام بندهای سند مادر، تمام ۲۱ بردار AVT یا همه ترکیب‌های ممکن ورودی را ندارد.

### ۳.۱ طبقه‌بندی ردیف‌ها

- **حالت ورودی قابل‌وقوع:** DT01-R1 تا R5؛ DT02-R1 تا R5؛ DT03-R1 تا R8؛ DT04-R1 تا R4 و R6 تا R7؛ DT05-R1 تا R7. این ردیف‌ها حالت‌های ورودی قابل‌وقوع را نشان می‌دهند؛ حتی اگر نتیجه مورد انتظارشان رد یا مسدودشدن باشد.
- **غیرقابل‌قبول به‌عنوان تصمیم پذیرفته‌شده:** DT01-R6 به‌جای Tier قطعی، حل‌نشده است؛ DT02-R6 و R7 مسدود/رد می‌شوند؛ DT03-R1 و R9 در وضعیت NS می‌مانند؛ DT04-R1 و R2 رد می‌شوند؛ DT04-R4 انتشار تجمیع قطعی را مسدود می‌کند؛ DT05-R2 تا R7 ناقص/نامعتبرند یا اجازه مؤثر شمردن کنترل را نمی‌دهند.
- **حل‌نشده از نظر هنجاری:** DT04-R5 باید `UNRESOLVED_NON_MATERIAL_NS` باقی بماند. این خروجی، نتیجه PASS آزمون است؛ زیرا مدل پرسش باز سیاست مادر را حفظ می‌کند و قاعده قطعی تجمیع اختراع نمی‌کند.

این برچسب‌ها فقط تعیین تکلیف مورد انتظار Fixture را توصیف می‌کنند و درباره امکان‌پذیری تجاری یا حقوقی یک Provider یا محصول واقعی نیستند.

## ۴. خواص بین‌ردیفی و Metamorphic

شش آزمون Metamorphic ثبت شده است:
۱. افزودن محرک بالاترِ درون‌دامنه نباید Tier انتخابی را کاهش دهد.
۲. ناقص یا نامعلوم‌بودن دامنه واحد تصمیم نباید Tier پایین‌تر و قطعی تولید کند.
۳. N/A مصوب باید برای تمام نامزدها از مخرج مؤثر یکسان استفاده کند.
۴. حذف یک فیلد الزامی از رکورد ریسک نباید کامل‌بودن آن را بهبود دهد.
۵. شواهد جزئی نباید امتیاز معیار والد تولید کند.
۶. مجوز مشروط آزمایش محدود، مجوز عملیاتی بعدی را اعطا نمی‌کند.

این آزمون‌ها مکمل آزمون ردیف‌ها هستند؛ فضای ورودی را به‌طور کامل پوشش نمی‌دهند و کامل‌بودن ریاضی را اثبات نمی‌کنند.

## ۵. جهش‌های هدفمند مشخصات

چهار خطای عمدی هدفمند بررسی می‌شوند تا مشخص شود Oracleهای منتخب، این انحراف‌ها را تشخیص می‌دهند یا خیر:
- انتخاب پایین‌ترین Tier به‌جای بالاترین محرک؛
- پذیرش خاموش Gate اجباری حذف‌شده؛
- تبدیل شواهد ناکافی به امتیاز صفر؛
- جایگزینی پروفایل کامل ریسک با حاصل‌ضرب صرف L×I.

جهش فقط زمانی کشته‌شده محسوب می‌شود که خروجی قابل‌مشاهده آن با Oracle جدول تصمیم مغایر باشد. این‌ها خطاهای دستی طراحی‌شده در ماژول آزمون مرجع‌اند؛ خروجی ابزار ثالث یا امتیاز متعارف Mutation Testing نیستند و جایگزین تمرین جداگانه MUT-01 تا MUT-10 در RDM-001 نمی‌شوند.

## ۶. ابهام‌های حل‌نشده و موارد خارج از پوشش صریح

RDM-004 عمداً موارد زیر را حل نمی‌کند:
- RDM-U01: نحوه قطعی/موقت برخورد با NS غیر‌بااهمیت، از جمله آزمون اهمیت، تفویض اختیار، انقضا و استفاده پایین‌دستی؛
- RDM-U02: Gate مشروط آزمایش در برابر N/A واقعی در یک مدل حالت هنجاری کامل؛
- RDM-U03: Schema اجباری کامل‌بودن واحد تصمیم؛
- RDM-U04: کالیبراسیون کیفی احتمال متناسب با هر حوزه؛
- RDM-U05: لنگرهای قابل‌اندازه‌گیری اختصاصی هر معیار برای امتیازهای ۱ تا ۵.

جدول‌های فعلی همه قواعد اتمی را به‌طور مستقیم پوشش نمی‌دهند. به‌ویژه RDM-R13/R14 (اختیار منبع، استقلال و اطمینان)، RDM-R17 (تفکیک نقش‌های Assurance) و RDM-R18 (ردیابی End-to-End تصمیم) به راستی‌آزمایی انسانی/ساختاری جداگانه نیاز دارند. هیچ نتیجه RDM-004 این شکاف‌ها را نمی‌بندد.

Booleanها و Enumهای مصنوعی جایگزین کفایت واقعی شواهد، تصویب، قابلیت اعمال، امکان اجرای محدودیت، اختیار و شواهد عملکرد کنترل هستند. Harness اسناد، هویت‌ها، تفویض اختیار، زمان‌مهرها، وضعیت حقوقی، اثربخشی کنترل یا ریسک واقعی را احراز نمی‌کند.

## ۷. سابقه اجرا و معیار پذیرش

دستور اجرا:

```bash
python tools/lot_eval_rdm004.py
```

اجرای GitHub Actions در Head دقیق باید این موارد را اجرا کند:
۱. اعتبارسنجی ساختار مستندات دوزبانه و لینک‌های محلی؛
۲. Harness موجود AVT/Mutation در RDM-001؛
۳. Runner جدول تصمیم RDM-004.

اجرای CI ثبت‌شده باید با SHA دقیق Head همان PR منطبق باشد. اجرای CI روی Head قبلی، تغییرات بعدی منبع را تأیید نمی‌کند. نتایج ردیف‌ها، آزمون‌های Metamorphic و جهش‌های هدفمند باید جداگانه گزارش شوند.

**قاعده پذیرش:** هر ۳۶ آزمون ردیف، هر شش آزمون Metamorphic ثبت‌شده و هر چهار آزمون جهش هدفمند باید روی Head دقیق PASS شوند. قبولی، صرفاً راستی‌آزمایی محدود همین Fixtureهاست؛ نه اثبات پوشش کامل ویژگی‌های ماتریس، کفایت استاندارد، تضمین مستقل، تصویب مالک یا آمادگی عملیاتی.

## ۸. حاکمیت و مجوزها

LOT-EVAL-001 همچنان PROPOSED است. تعیین تکلیف مالک برای REV-01 تا REV-14 تا زمانی که مالک جداگانه ثبت نکند، PENDING باقی می‌ماند. هیچ Provider، نامزد، فناوری، حوزه قضایی، قرارداد یا پایلوتی انتخاب نشده است. هیچ خرید، اتصال شریک، داده Production، فعالیت مالی، Merge یا Deploy مجاز نشده است.
